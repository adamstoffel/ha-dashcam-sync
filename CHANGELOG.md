# Changelog

All notable changes to the integration and the app. Both are released together with the same CalVer version (`YYYY.M.patch`).

## Unreleased

- Integration tests now run on Python 3.14 against Home Assistant 2026.10 (newest test package), like Home Assistant itself; they ran against 2026.2 before. That surfaced API changes, now adopted: schemas use `probatio` (Home Assistant's validation engine), camera devices link to the hub with `via_device_id` (the tuple form is deprecated for 2027.8), constants are imported from their `const` modules, and repairs flows return `RepairsFlowResult`.
- The network check probes each address once and the point-to-point candidates in parallel, so picking an address stays well inside the integration's request timeout even when several are taken. `install-on-ha.sh` versions carry seconds and always exceed the installed version, so two installs in the same minute still rebuild.
- Review fixes: a sizeless recording is matched by path only when its file name carries the time, so a camera that reuses a name (`clip.mp4`) still gets new recordings; a finished copy is reused only when its bytes match, never another clip of the same name and size; a part file that already holds the whole clip finishes when the camera answers 416; the verified size and the exact file name chosen (which may be a `_2`) are saved before placing, so a crash between placing and recording adopts that file instead of downloading it again; a 416 recovery keeps only the bytes up to the saved offset; a 416 that states another size never confirms a download; the installer stages both parts and swaps them in, restoring the previous version on failure; `check_ha_api` counts only module-level names.
- App log: a resumed download is now visible. The app logs when a clip is kept after an interruption (`kept N bytes of …; it resumes on the next visit`), when a visit resumes it (`resuming … at byte N`), when it finishes after a resume, and one summary line per visit (`session ok: 3 clip(s), 120.3 MB, 1 resumed, 0 failed`). Before, a successful visit and a resume left no trace in the log.
- Fixed: the partial download of a clip the camera has since overwritten (loop recording deletes its oldest files) stayed on disk forever, because the catalogue kept pointing at it. The next listing now drops partials of clips the camera no longer lists (an empty listing is not trusted, nor one where a folder could not be read or a listing limit was hit: drivers report whether their listing was complete).
- Fixed (SGK cameras): clip times were 16 hours off. The camera's listed timestamp is computed as if its local clock were UTC+8; the time is now read from the file name (the same as the stamp in the video) in Home Assistant's time zone. Clips without a trustworthy listed size are matched by path, so corrected times never cause a second download, and times of already downloaded clips are corrected on the next visit. The image installs tzdata explicitly.
- Fixed (SGK cameras): a photo was filed as an event clip and opened in the video player. The camera answers a folder it lacks (`emr`) with its photo list; files are now typed by their own path (`.jpg`/`Photo/` is a photo, `Normal/` is loop recording) and listed once. Already downloaded clips get their type corrected on the next visit, every clip stores its verified size, and photos open as an image (**View**).
- Fixed (SGK GK720X cameras): every clip failed with "the camera's sizes disagree", because the file list gives kilobytes for videos and an unrelated number for photos. The Viidure listing size is now only an estimate for progress; each download is verified against its own Content-Length and Content-Range, and the verified size is stored. A resume with an unknown listing size no longer restarts from byte 0, and the progress line no longer shows "0 B left · about 0 s".
- Fixed: joining a password-protected camera hotspot was always refused by the Supervisor ("extra keys not allowed @ data['wifi']['method']"). The Supervisor client library sends the Wi-Fi security as `method`, but the Supervisor expects `auth`; the integration now sends the key the Supervisor accepts, and the tests check every request against the Supervisor's own schema.
- **Point-to-point addressing** for hotspot cameras whose range sits inside your home network. When an address in the small block around the camera is taken at home, the app now picks one free address next to the camera as a /32 and joins with the camera as gateway (a direct route to it), so only two addresses are claimed instead of four. New camera option `addressing` (`auto` by default, `block`, `point_to_point`); `static_address` can fix the address. The pick is remembered and changes only when it becomes taken. Network check shows the shape and the claimed addresses.
- Viidure driver: works with SGK GK720X firmware (from a real probe): camera at 192.168.0.1 (now a default address and a wizard choice), firmware read from `/app/getdeviceattr`, card space reported in MiB, the live stream named by `/app/getmediainfo`, no event or parking folders and no playback mode. When the camera cannot pause recording, the clip it is writing is left for the next visit instead of failing the size check.
- The camera wizard no longer offers DHCP addressing for hotspot cameras: the join always writes a static address, so the camera's gateway and DNS never replace your own. Joins for one camera no longer overlap, and unloading the integration stops a running join or scan.
- Fixed: on a real Home Assistant, edits from the panel (adding a camera, Settings, pausing, the storage location) only took effect after an app restart; the wizard then answered "unknown camera". The Supervisor stores saved options but only writes `/data/options.json` when the app starts, so the app now writes that file itself after the Supervisor accepts the options, and picks up Configuration-tab edits within about 15 seconds. The fake Supervisor in the tests now behaves the same way, so this is covered.
- Wizard: **Scan** asks Home Assistant to scan (this app's role may not), and lists networks with signal strength; the hotspot step asks for the camera's IP (Novatek 192.168.1.254 or Viidure 192.168.169.1 offered, or any other), since Home Assistant's address on the camera network is chosen next to it; the Connect step shows the interface's state and, after 90 s without an answer, what to check. An idle interface reads "not configured · free" instead of "disabled", and notices that are not errors are no longer shown as errors.
- A panel edit made right after a Configuration-tab edit no longer overwrites it; a save the Supervisor refuses is reported as such, naming the field.
- Configuration tab: the camera dialog preselected Addressing *auto* and a per-camera Sync mode *events_only*; the safe defaults (*static*, *events_first*) are now first.
- `scripts/install-on-ha.sh`: install or update from any branch in one command.
- Wording: the Configuration tab's labels and descriptions use the panel's terms (Camera hotspot / Local network, Wi-Fi interface, Camera SSID, disk or share) and point to the panel; the docs describe the panel as the place to configure, with YAML as the alternative. The integration's Wi-Fi option becomes **Re-join a camera's Wi-Fi** (new cameras join from the wizard), and its manual steps no longer claim the panel shows the Wi-Fi password.
- Panel: a **Settings** page for sync (what to download, recent minutes, deleting from the camera, and remux/thumbnails/keep-original under Advanced), storage (where clips are kept, the local folder, the attached disk or share, spooling) and retention (size cap, minimum free space, days per kind, for each target in use, and the purge time). Values are checked in the page before saving; the API checks them again and names the field. The Storage page keeps health, moving clips and purging. API: `GET/PATCH /settings`. Negative retention values are now refused.
- Panel: a step-by-step camera wizard (Connection: Camera hotspot / Local network; Details; Name with an Advanced section; Connect). The Wi-Fi interface is chosen from what Home Assistant reports instead of typing `wlan0`; the ID is derived from the name; cameras are edited in the same steps, keeping the stored password when it is left empty. Camera cards show connected / not in range, last sync and errors, with less-used actions under **More**; results are formatted instead of raw JSON, and a device profile downloads as a file.
- Hotspot join from the wizard: the app asks the integration (a `join_wifi` push), which runs the address check, checks the interface and writes the profile, then reports back. When it cannot (integration not connected, no answer in 45 s, Supervisor client unavailable), the wizard shows the exact profile with copy buttons and continues when the camera answers. API: `GET /wizard/interfaces`, `POST/GET /cameras/{id}/join`, `POST /cameras/{id}/join-result`.
- App: interrupted downloads, audited and hardened, each with a fault-injection test that fails on the previous code:
  - a camera that states no file size could have a cut-off download recorded as complete; completeness is now confirmed by asking for the bytes after the end;
  - a body that ended early was thrown away; it is now kept and resumed;
  - a partial answer from the wrong offset would have been spliced in; it is now refused (and one that restarts from byte 0 restarts the file);
  - a crash between placing a file and recording it caused a full re-download and a hidden duplicate; the placed file is now adopted;
  - after a remux the original was deleted before the clip pointed at the new file, so a crash could leave a clip pointing at nothing; the order is reversed, and clips left that way by older versions are repaired at startup;
  - shipping to a disk or share could leave `_2` duplicates after a crash; a finished copy is now reused;
  - partial downloads nothing will resume and temporary copies from crashed runs are cleaned up at startup.
- App: change where clips are stored from the panel (Storage › Location: local folder, a network share or attached disk, or both), and **Move clips** to bring existing clips to the new place. Each copy is size-checked before the old one is deleted; the move is resumable, cancellable, refuses to start when the destination is missing, and takes turns with shipping, retention and deletes. API: `GET/PATCH /storage/location`, `GET/POST/DELETE /storage/migration`, and `migration` push events.
- App: validation errors from the API now name the field and the reason instead of "1 validation error".
- App: a local disk added in Home Assistant (**Settings › System › Storage › Add storage › Local disk**: a USB drive, SD card or internal drive) can now be the second storage target, not only a network share. The same safety rule applies: it must be mounted at exactly that folder, so a missing disk never fills the system disk.
- Integration: fixed the integration failing to load on Home Assistant 2026.11 (`cannot import name 'async_extract_referenced_entity_ids' from 'homeassistant.helpers.service'`). The helper now comes from `homeassistant.helpers.target`, which exists in both older and newer releases.
- CI: a new check that every Home Assistant name the integration imports exists in the minimum supported version (`scripts/check_ha_api.py`), and a nightly run against the newest release. The tests only ever ran on an older Home Assistant than the one the integration claims to support, which is how the above got through.
- App: an optional **Integration token** option, so the integration can be added by hand when discovery does not appear (the previous instructions pointed at a token that was never logged). The token is never logged; the log now says when discovery was offered.
- Tests: two timing assumptions removed (the WebSocket snapshot reply could be preceded by another push; the Novatek heartbeat test assumed a fixed delay).

## 2026.11.0

First version. See `app/dashcam_sync/CHANGELOG.md` for the app side.

- Integration: Supervisor discovery, config/options/reauth/reconfigure flows, devices per camera, translated entities (sensors, event, image, live camera, buttons, switch, select), media source, actions (`sync`, `keep_clip`, `unkeep_clip`, `delete_clip`, `purge`), diagnostics, repair issues with fix flows, and a "Notify on new dashcam event clip" blueprint.
- Found and fixed by the end-to-end, browser and property-based suites before release:
  - the app took ~30 s to stop while an integration was connected (WebSockets are now closed on shutdown);
  - switch and select changes did not reach Home Assistant while the socket was live, and app-level issues (unsupported camera, storage low) were never pushed: hub state is now pushed and writes force a fresh read;
  - `last_event_clip` was not pushed, and neither it nor `last_sync` survived an app restart;
  - the address-block check returned a misleading result for LAN cameras;
  - a non-list `cameras` option crashed option parsing;
  - a malformed WebSocket frame could drop the integration's socket;
  - a status read answered just before a push could land after it and undo it, so a finished sync could show as never having run until the next change (pushes and status reads now carry a `rev` order number, and a pushed state replaces a status answer only if it is newer);
  - four hassfest errors (services target filter, HTML-like and URL text in translations, `fix_flow` beside `description`).
- Found by an independent code review, each fixed with a regression test that fails without the fix:
  - fresh clips from a camera with a reset clock were purged straight after download (age is now counted from download time at the earliest);
  - a deleted or purged clip was downloaded again at the next visit (deletions now leave a tombstone);
  - an unexpected error was recorded as a successful sync and could end a camera's worker for good (the worker now survives any tick, and unexpected errors are failed sessions);
  - *Restore recording* and *Sync now* were ignored once the retry backoff was exhausted;
  - clips still being remuxed could be copied to the NAS as raw `.ts` without thumbnail or sidecar;
  - a failing callback or a renamed `local_folder` could kill shipping and post-processing until restart; interrupted post-processing now resumes on start;
  - the host check could be bypassed with userinfo (`ip:x@internal-host`) or IPv4-mapped IPv6 addresses;
  - `PATCH /cameras/{id}` accepted invalid values that made the camera vanish on reload;
  - mount probes ran on the event loop, so a hung share could freeze the API and every download;
  - the panel's camera selector sent you to the Overview.
- Integration fixes from review and end-to-end testing, each with a regression test:
  - switch, select and button changes could be delayed up to 10 s by the coordinator's refresh debounce (writes now refresh immediately);
  - events pushed by the app were answered from a stale cache instead of refreshing;
  - one malformed push message (or a malformed snapshot) could end live updates or poison the state: messages and snapshots are shape-checked;
  - the app's instance id is no longer derived from the API token, so rotating the token no longer breaks *Reconfigure* or creates a duplicate entry;
  - non-JSON or wrongly shaped API responses now fail cleanly (setup retries instead of failing);
  - the arrival-hint entity can be cleared again; the Wi-Fi kill switch carries on after one camera fails; the hub device cannot be deleted from the UI; network-storage entities appear when a share is added after setup; image paths are resolved off the event loop.
- Hardening: the wizard refuses public, loopback and Home Assistant-internal hosts; option edits are serialised.
- Push updates over a WebSocket with a 30 s poll as the fallback.
